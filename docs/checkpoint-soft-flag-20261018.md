## 1. 事故：球数守恒公式算错

`server/checkpoint.js` 里我写的是

```js
if (state.balls.length !== state.spawnCount + state.loopCount - state.merges) fail();
```

但无尽模式的「循环合成」（两个完全体相撞 → 变回一个社徽）在 `processMergeQueue()` 里
**同时做了 `merges++` 和 `loopCount++`**，所以 `loopCount` 已经被算进 `merges` 里了。
正确形式是

```js
if (state.balls.length !== state.spawnCount - state.merges) fail();
```

后果：**无尽模式只要造出两个完全体并让它们相撞，此后每一次存档都 400**，客户端
`RunConnection.blocked = true` → 本局永久暂停；刷新后 resume 会回滚到循环之前的状态，
再玩到循环又触发。整局报废。

### 线上影响（nginx access.log 实测）

| 时段 | `/api/run/checkpoint` 400 数 | 独立 IP |
|---|---|---|
| 15:34:25 — 16:06:05（错误版本在线的 31.7 分钟） | **78** | **7** |
| 16:06:05 之后（修复上线） | **0** | 0 |

同一套检查还有第二个触发点：**秘技**（`useSecret()` 直接删球，既不改 `merges` 也不改
`trace`），撞破球数守恒和单位守恒。红队用真实物理 + 真实 HTTP 复现过。

### 为什么之前没被发现

- 部署到被举报只隔了 32 分钟，而**正常人要打很久才会造出两个完全体**：完成态里
  `loop_count > 0` 的对局一共 9 局，全部早于这次部署。
- 老代码把 `validateCheckpoint` 的所有失败原因**吞成一句固定文案**，日志里看不出是哪一条
  检查挂的。红队说「我为此花了最多时间」——他们是对的。

## 2. 修法：把校验分成「硬」和「软」两类

这是这次真正的设计变更，不是补一个公式。

| | 硬校验（失败 → 400） | 软校验（失败 → 标记可疑） |
|---|---|---|
| 内容 | 结构/类型/取值范围、单调性、`elapsed` 与墙上时间一致、终局不可变、`trace` 不可改写、秘技次数不超发 | 球数守恒、单位守恒、`validateRun`、投放间隔<350ms |
| 理由 | 真实客户端**永远**满足；不满足说明数据不可信或会让服务器存下畸形状态 | 这些是**启发式判定，不是证明**；已经各打死过一次真实玩家 |
| 代价 | 玩家这一局结束 | 玩家这一局照常玩完，提交时进复核、不上榜 |

> **原则：启发式的代价只能是「进人工复核」，不能是「报废玩家的对局」。**

实现：`validateCheckpoint` 返回 `{ state, flags }` 而不是直接抛；`sessions.js` 把 flags
累积到 `live_game.flags` 新列；`submit` 时和 `validateRun` 的 flags 合并成
`run.flag_reason`，`suspicious=1` → 榜单查询本来就 `WHERE suspicious = 0`，自动不上榜。

另外补了三件事：

1. **每条硬校验失败都自报家门**（`fail('结构: 球 1.x 非法')`），`sessions.js` 写进
   `console.warn`，但返回给玩家的仍然是统一文案（不泄露内部结构）。
2. **空对局不再算可疑**：开局就退出的 0 分记录以前会被标成 `suspicious=1`，每天几十条噪音。
3. 秘技感知：用了秘技的对局，守恒律退化成只查上界（删除量服务端无法核验）；秘技次数由
   分数唯一决定，攻击者不能凭空多要。

## 3. 我不打算做的两件事（都测过了）

### 3.1 服务端重放 —— 分辨不出真假

`server/sim/game.js` 是完整移植，所以「服务端按 trace 重放一遍」听起来可行。实测：

| 场景 | 声称 | 重放 |
|---|---|---|
| 真实对局 seed 4242 | score 836 / merges 202 | 860 / 202 |
| 真实对局 seed 777 | 837 / 212 | 932 / **230** |
| **真实对局 seed 99991** | **1065 / 255** | **592 / 145**（Δ −110 次合成） |
| 伪造（真 trace + 落点全塞中间 + 分数 10×） | 2510 / 251 | 719 / **176** |

**真实对局的偏差（−110 次合成、−44% 分数）比伪造的偏差还大**，做不了判决器。

原因是根本性的：Matter.js 用固定步长但**必然依赖 `Math.sin/cos/atan2`**，这些函数在
Chrome / Safari / Node 之间不是逐位一致的；再加上 trace 里 `x` 只存到 4 位小数、
`t` 只存到毫秒，重放一开始就偏移，混沌系统会把这点偏差放大到完全不同的棋盘
（实测 252 次投放后，50 颗球里只有 2 颗位置能对上）。

**结论：客户端跑物理的游戏，服务端无法证明结果。** 这不是实现问题，是数学边界。

### 3.2 score/merges 阈值 —— 会打死真人

思路：真实合成平均 2.99 分/次（`BASE_COEF`），伪造按 `10×merges` 报。线上 216 局实测：

```
p50 = 4.19   p90 = 4.33   p99 = 5.81   ← 到这里都很干净
max = 8.295                            ← 一位真实玩家（classic 4811 分 / 580 次合成，靠共鸣拿分）
攻击者 = 10.0                          ← 只比真实最大值高 1.21 倍
```

安全余量 21%，不够。这条阈值一上线，那位 4811 分的玩家立刻掉榜。

## 4. 那么还剩什么防线

按"实际挡住的东西"排序：

1. **墙上时间** —— 每次投放 `elapsed` 只增不减、且 `elapsed ≤ (now − started_at) + 1500ms`。
   攻击者要拿 n 次投放，就必须真等 `390ms × (n−1) − 1.5s`。这是唯一无法伪造的成本：
   打 5159 分要 86 秒，打 38 万分要 1.94 小时。**这是唯一一条真正有效、且不会误伤的防线。**
2. **`validateRun` 统计上界** —— 投放等级序列必须来自加权池，「全 Lv5 刷 660 万分」被挡在
   折算单位的统计上界（8σ）上。
3. **软校验 + 人工复核** —— 守恒律、`validateRun`、投放间隔指纹；可疑的对局照样入库、
   照样能查、只是不上榜。误杀可以人工放行（`/api/admin/clear-flag`）。
4. **投放间隔**（⚠️ 比我一开始以为的弱得多）
   - 线上 217 局真实对局实测：最短间隔 **min = 400ms、p1 = 400ms**，一局都没低过 400
     （前端 `DROP.cooldownMs = 400` 是硬栅栏）。所以把服务端阈值从 350 收紧到 **390**：
     229 条历史对局回放，判定变化**只有 2 条**，就是那两条 19999 的渗透记录，零误伤。
   - 但**别把它当测谎仪**：线上有 **42 局真人的中位间隔就在 400–416ms**（顶着冷却连点）。
     拿中位间隔做阈值，<500ms 误杀 20 局、<600ms 误杀 37 局。一个"每 400ms 投一次的脚本"
     在时间维度上和这 42 个真人是同一分布，区分不了。

明确做不到的：

- **服务端重放**（3.1 已测）—— 真实对局的偏差比伪造还大。
- **任何"服务端发探针、客户端报结果"的方案** —— 要判定就得模拟，一模拟就回到 3.1。
- **一个真的会玩这游戏、并且完美控制输入节奏的 bot，服务端区分不了。**

这种游戏的最终防线只能是「头部成绩人工复核 + 社团内部的社会约束」，不是密码学。

## 5. 攻击现在到底有多贵（每秒得分视角）

墙上时间是唯一不可伪造的成本，所以真正的度量是「每秒得分」。线上 219 局真实对局：

```
每秒得分    min=0.81  p50=1.60  p90=5.87  p99=9.16  max=9.32
每次投放得分 min=2.99  p50=3.94  p90=4.15  p99=5.64  max=7.85
每球秒数    min=0.41  p50=2.49  p90=3.49  p99=4.26  max=4.80
```

现有上界 `score ≤ 1.15 × 2.9873 × U`，而 `U ≤ 3.89n`、`n ≤ 时长/0.39s`，
所以隐含的每秒得分上限是 **≈34.4 分/秒**，而真人最多 9.32。

| 目标 | 真人花了多久 | 攻击者按上界只需 | 倍数 |
|---|---|---|---|
| classic #1（4948） | 数十分钟 | **2.4 分钟** | — |
| endless #1（18454） | **103.9 分钟** | **8.9 分钟** | 11.7× |

**结论：现在这条防线的强度就是"攻击者愿意等几分钟"。** 想把它变贵只有两条路，
两条我都算过，收益都很小：

- 把 `TOLERANCE` 从 1.15 收到 1.0 → 上界降 13%，头部真实对局的 `score/U` 是 2.386，
  仍有 1.25 倍余量。**只贵 13%。**
- 按"每秒得分"设阈值（比如 15 分/秒）→ 攻击者要多花 2.3 倍时间，但真人单球最高 7.85 分、
  最快 0.41 秒/球，理论上限能到 19 分/秒，**会压到未来的高手**。

所以别指望再靠加校验解决。剩下的只能是「头部成绩人工复核 + 社团内部社会约束」。
