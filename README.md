# 合成大元火

元火动漫社的内部小活动：一个「合成大西瓜」类的网页游戏，带两个排行榜
（活动·经典模式 / 岗位·无尽模式）、在线对局恢复、隐藏道具与首次出现图鉴。

比赛在 2026-10-17 上线、10-31 12:00 截止，**15 天里 187 个玩家提交了 598 局**。

## 文档

- [攻防复盘](docs/ATTACK-DEFENSE-REVIEW.md)：作弊手法、判据体系、红队对抗、误区复盘
- [游玩数据分析](docs/GAMEPLAY-ANALYTICS.md)：15 天 598 局的留存、时段与单局画像

其余专题文档见 [docs/README.md](docs/README.md)。

## 为什么这个仓库值得看

**重点不是游戏本身，而是那 15 天的攻防**——一个跑在公网、允许客户端自己算物理的
小游戏，服务端在只能「事后猜」的前提下尽可能判别真伪。

## 有意思的几个点

**1. 协议 2 的根本困境。** 为了手感和移动端性能，线上跑的是客户端权威物理：
浏览器自己跑 Matter.js，把结果 state 上传。服务端拿到的是一个自洽的成品，
只能反推它合不合理。所有判据都是在这个前提下能拿到的最好结果，不是根治。

**2. 真正有效的判据是结构，不是阈值。**
- **台账不变量**：由 trace 和终局球阵可以唯一确定合成数与分数的上界。真人局这条等式精确成立（比值 1.00），所以容差只给了 1.02。
- **物理推演**：服务端拿同一份种子和操作序列复算，采样 12% 的存档窗口。真人每窗口偏差标准差 0.48–1.33 次、均值为零，所以 4σ 判据既灵敏又安全。累计跑了 31,144 次窗口。
- **落点统计**：真人一整局落在几百个不同横坐标上（实测最少 158 种），脚本只会落在少数硬编码位置。

**3. 硬校验只用于「不可能发生的状态」，其余全部软标记。**
误判的代价不对称：把真人判成作弊，玩家丢掉一整局（我们犯过 5 次）；
把作弊漏判，只是榜单上多一个假分，事后还能追认。

**4. 我们自己的误判比作弊更难对付。**
13 天里有 5 类判据因为「判定时机错了」把真人判成作弊，
全部是同一个病——把整局性质的东西判在了中途。这条写进了
[§8.1 判据要按判定时机分类](docs/ATTACK-DEFENSE-REVIEW.md)。

## 跑起来

需要 Node 22.12+。

```bash
npm ci
npm run dev            # http://127.0.0.1:5173/?mock=1 用本机演示榜，不写服务器
```

跑后端：

```bash
npm run build:server-game   # 把 web/src/game.ts 编译成 server/sim/
node server/index.js        # 默认 127.0.0.1:8787，自己建 server/data/
```

测试：

```bash
npm test                 # 132 个单测，含判据、台账、物理推演
npm run test:anticheat   # 反作弊专项
npm run build            # 产出 web/dist + server/sim
```

演示模式（`?mock=1`）完全不连服务器，适合只改前端。

## 目录

| 路径 | 内容 |
|---|---|
| `web/` | 前端：Vite + TypeScript + Matter.js + **手写 Canvas 2D 渲染**（刻意没用 Matter.Render） |
| `server/` | 后端：Node 原生 `node:http` + 内置 `node:sqlite`，**零第三方依赖** |
| `server/validate.js` | 全部判据常量与纯函数。每条常量上方写着标定依据和余量 |
| `server/checkpoint.js` | 逐存档点校验 |
| `server/sessions.js` | 会话、物理推演抽样、规避检测、终局类判据 |
| `tests/` | 132 个测试 |
| `docs/` | 攻防复盘与三份专题文档 → [索引](docs/README.md) |
| `data/` | 匿名化的游玩数据（598 局）→ [说明](data/README.md) |
| `tools/` | 标定、测量、数据导出、报告生成 |
| `deploy/` | Nginx 与 systemd 样例（域名、路径已占位符化） |

## 关于数据

`data/` 里是比赛期间全部提交记录的匿名版：玩家身份换成 `p0001` 这样的编号，
不含昵称、设备标识、IP 或操作序列。原始库里也没有采集浏览器指纹。
细节见 [docs/PLAYER-DATA.md](docs/PLAYER-DATA.md)。
